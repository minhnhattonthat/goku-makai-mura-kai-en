# Skill gotchas

One line each: the reference it belongs in, then the fact.

- `scripts/gim.py` (fix stranded in `tools/gim.py`): `walk()` only attaches a palette to an image that came first; this game's character GIMs store the palette block first, so 325 of 1,064 textures failed with `'NoneType' object is not subscriptable`. Keep a pending palette for the next image.
- `references/setup.md`: `fetch_emu.py ppsspp` failed with `CERTIFICATE_VERIFY_FAILED` on this Windows Python; `SSL_CERT_FILE=$(python -c "import certifi;print(certifi.where())")` fixes it.
- `scripts/iso9660.py`: its CLI has no usage text; `x` needs three arguments (`x ISO OUTDIR`) and `patch()` can only move the file that grew, not a smaller neighbour (`docs/re/kpd.md`).
- `SKILL.md` Tools table: `sheet.py` does not take texture PNGs by directory (it wants `f<frame>.png`), so texture contact sheets needed a separate labelled, deduping script (`tools/gimsheet.py`).
- `scripts/psp.py` (worked around in `tools/debug/pspsession.py`): `WS.recv` does `json.loads` on every frame, so a raw Shift-JIS log event raises `UnicodeDecodeError`, and it ignores opcode 8: a WebSocket close (the emulator exiting) surfaces as a decode error on bytes `03 e9`. Handle op 8 and decode with errors='replace'.
- `references/emulator-qa.md` §PPSSPP: on PPSSPPHeadless `cpu.resume` drops the debugger connection; `cpu.runUntilTime` is the only way to run, and it did not stop at a `cpu.breakpoint.add` breakpoint in my test, so code breakpoints gave no caller traces. `memory.write {address, base64}` works on code too (the new instruction ran), so RAM patches at safe points are the usable hook.
- `references/emulator-qa.md` §Debug tool: PSP warp pattern that worked: find the process factories, then redirect one `jal` through a stub in free RAM (0x08800100), no ROM patch. Rare text: copy a string to scratch RAM and wrap the table's u32 offset backwards to it, in any real text box.
- `SKILL.md`: `sheet.py DIR` wants `f<frame>.png`; pass explicit PNG paths for named shots, and it writes `sheet.png` beside the first file, so an old sheet there gets replaced.
- `references/emulator-qa.md` §PPSSPP: PPSSPPHeadless exits on a game SIGSEGV; psp.py only sees the closed socket (a decode error on `03 e9`), but `ppsspp.log` holds the faulting PC and MIPS call stack. Read it before guessing.
- `references/emulator-qa.md` §Debug tool: forcing a menu over a live stage can skip the resource state the real flow sets up; a process that crashes when pushed may work when it replaces the stack (mode 2), as the real flow does.
- `references/pipeline.md` §Recon (code = font cell): template matching kanji cells against MS Gothic failed outright on a bold, outlined 18x16 font (nearly every cell matched a dense wrong kanji, even after blurring); a sheet with the table character drawn under each cell (`tools/fontcheck.py`) read 16 rows in 4 images and found the one misread.
- `scripts/tbl.py`: aliased codes (two codes on one font cell, e.g. two digit ranges) roundtrip, but a non-canonical 2-byte alias decodes as `[80]` plus the trail byte read as a 1-byte glyph; order the table so the codes the script uses come first.
- `references/pipeline.md` §Repo layout: on Windows `Path.write_text` writes CRLF; pass `newline="\n"` when a generator writes a table or JSON, or every regenerate shows a whole-file diff.
- `references/platform-psp.md` (font): Capcom's PSP `bft` font index stores `{0,x,y,w,h}` per glyph and the renderer uses `w` as both the sheet rect and the advance, so a VWF is a bft-only edit (trim each rect to its ink + 1 px); centring follows. Check whether a font's per-glyph width field is the advance before planning code hooks.
- `references/pipeline.md` §Width gate: a ruler fill (`A123456789B123456789...`) in every text run, with the id first, measured every box in one tour; the engine's own auto-wrap (mid-word) showed each box's wrap width directly, no box-edge guessing.
- `references/pipeline.md` §Marker: the marker id needs characters the font has; `[ ]` were missing here (and `tbl.py` reads `[XX]` as a hex escape anyway), so markers use `( )`.
- `references/platform-psp.md` (PRX strings): a PRX's data pointers are plain u32 words (vaddr = file offset - 0x80 for a segment at file 0x80) with an R_MIPS_32 reloc each; rewriting the word to another in-module vaddr relocates correctly, so a long string can move into free slot space with no code change (proven in the save dialog). Scan for lui/addiu pairs and mid-string pointers before trusting a table.
- `references/graphics.md` §When the text is a texture: reusing an official USA PSP release's art on the JP code, the USA button-icon textures swap circle and cross (USA OK is cross); splice per GIM and keep the JP icon textures, never whole files. A USA title atlas packed another way drew the wrong label in a JP sprite rect: check each reused texture in game against the original shot.
- `references/graphics.md` / `sheet.py`: sheet.py drops alpha, so white lettering with alpha shows as a blank white tile; composite on a dark backdrop (`tools/gfxshow.py` here, or `showgim.py`).
- `references/graphics.md` §Lettering: letters cut from the game's own English art (column runs at alpha >= 128, touching pairs split at the faintest column, rim +1 px) composed new words that match the original exactly (`tools/gfx.py` Font); cheaper and closer than any TTF.
